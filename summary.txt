================================================================================
       DEEP GALERKIN METHOD FOR MULTI-ASSET EUROPEAN OPTION PRICING
                        — DETAILED PROJECT SUMMARY —
================================================================================

This document explains the entire project from first principles. It is written
for someone who may not be familiar with computational finance, PDEs, or neural
network PDE solvers. Every design decision is explained with the reasoning
behind it.


================================================================================
PART I — THE PROBLEM
================================================================================

1. WHAT IS AN OPTION?
---------------------

An option is a financial contract. A European call option gives the holder the
right (but not the obligation) to buy an asset at a predetermined "strike price"
K at a future date T (the maturity). If the asset price at maturity S(T) is
above K, the holder profits S(T) - K. If S(T) is below K, the option is
worthless (the holder simply doesn't exercise it). So the payoff is:

    Payoff = max(S(T) - K, 0)

The central question of mathematical finance is: what is the fair price of this
option TODAY, before the future is known?


2. HOW ASSET PRICES ARE MODELED (BLACK-SCHOLES MODEL)
-----------------------------------------------------

The Black-Scholes model assumes each asset price S_i follows a "geometric
Brownian motion" under the risk-neutral measure:

    dS_i = r * S_i * dt + sigma_i * S_i * dW_i

Where:
  - r is the risk-free interest rate (e.g., 5% per year)
  - sigma_i is the "volatility" of asset i (how much it fluctuates)
  - dW_i is a Brownian motion (random walk)
  - <dW_i, dW_j> = rho_ij * dt models the CORRELATION between assets

The key insight: under this model, the option price V(t, S) at any time t
satisfies a PARTIAL DIFFERENTIAL EQUATION (PDE). This is the famous
Black-Scholes PDE.


3. THE BLACK-SCHOLES PDE
------------------------

For a SINGLE asset:

    dV/dt + (1/2) * sigma^2 * S^2 * d2V/dS2 + r * S * dV/dS - r * V = 0

With the boundary condition V(T, S) = max(S - K, 0) at maturity.

This PDE has an EXACT closed-form solution for one asset (the Black-Scholes
formula). But for MULTIPLE correlated assets (d assets), the PDE becomes:

    dV/dt + (1/2) * SUM_{i,j} rho_ij * sigma_i * sigma_j * S_i * S_j
            * d2V/(dS_i * dS_j) + r * SUM_i S_i * dV/dS_i - r * V = 0

This is a PDE in d+1 dimensions (time + d asset prices). For d > 3, traditional
numerical methods (finite differences, finite elements) become COMPUTATIONALLY
IMPOSSIBLE because they require a grid of points in d-dimensional space. The
number of grid points grows as O(N^d) — this is the "curse of dimensionality."


4. WHY NEURAL NETWORKS?
------------------------

Neural networks can approximate functions in high-dimensional spaces without
the curse of dimensionality. Instead of discretising space on a grid, we:

  1. Represent the solution V(t, S) by a neural network V_theta(t, S)
  2. Sample random points in the domain
  3. Compute how well V_theta satisfies the PDE at those points
  4. Optimise the network parameters theta to minimise the PDE residual

This is the core idea of the Deep Galerkin Method (DGM).


================================================================================
PART II — THE LOG-PRICE TRANSFORMATION
================================================================================

5. WHY WE TRANSFORM TO LOG-PRICE COORDINATES
---------------------------------------------

The raw Black-Scholes PDE has variable coefficients — terms like S^2 * d2V/dS2
where the coefficient depends on S. This makes it harder for a neural network
to learn accurately because the magnitude of the PDE terms varies wildly across
the domain.

We perform the change of variables:

    x_i = log(S_i / K)

So x_i = 0 means the asset is at the strike price (at-the-money), x_i > 0
means in-the-money, and x_i < 0 means out-of-the-money.

We define u(t, x) = V(t, K * exp(x)).

The PDE in log-price coordinates becomes:

    du/dt + (1/2) * SUM_{i,j} rho_ij * sigma_i * sigma_j * d2u/(dx_i * dx_j)
          + SUM_i (r - sigma_i^2 / 2) * du/dx_i - r * u = 0

The KEY advantage: all the coefficients are now CONSTANTS:
  - Diffusion tensor:  A_ij = rho_ij * sigma_i * sigma_j  (constant)
  - Drift:             mu_i = r - sigma_i^2 / 2           (constant)

This makes the PDE much easier for the neural network to learn.


================================================================================
PART III — THE DEEP GALERKIN METHOD (DGM)
================================================================================

6. THE DGM LOSS FUNCTION
-------------------------

We train the network by minimising the PDE residual. The total loss is:

    J(theta) = lambda_PDE * J_PDE + lambda_boundary * J_boundary

Where:

  J_PDE = (1/N) * SUM_k |L[u_theta](t_k, x_k)|^2

This is the mean squared PDE residual. L[u] is the differential operator:

    L[u] = du/dt + (1/2) * SUM A_ij * d2u/(dx_i dx_j) + SUM mu_i * du/dx_i - r*u

If u perfectly satisfies the PDE, L[u] = 0 everywhere. We want it to be as
close to zero as possible.

  J_boundary = (1/N) * SUM_k |u_theta(t_k, x_k)|^2    at boundary points

For call options, when any asset price goes to zero (S_i -> 0, i.e., x_i -> -inf),
the option becomes worthless: V -> 0. This is the boundary condition.


7. THE DGM NETWORK ARCHITECTURE
---------------------------------

The DGM architecture (Sirignano & Spiliopoulos, 2018) is NOT a standard
feedforward neural network. It uses a special "gated" architecture inspired
by LSTMs (a type of recurrent neural network).

WHY NOT A STANDARD NETWORK?

In a standard MLP (multi-layer perceptron), the input passes through layers
sequentially. By the time it reaches layer 5 or 6, the network has "forgotten"
the original input. But for PDE solving, we need accurate DERIVATIVES of the
output with respect to the input (du/dt, du/dx, d2u/dx2). If the network
loses track of the input, these derivatives become noisy and inaccurate.

THE DGM SOLUTION: RE-INJECT THE INPUT AT EVERY LAYER

The DGM architecture feeds the original input [t, x] into EVERY hidden layer,
not just the first one. Each layer receives:
  - The original input [t, x]
  - The hidden state S from the previous layer

And produces an updated hidden state S' using four "gates":

  Z = sigma(U_z * [t,x] + W_z * S + b_z)     — carry gate
  G = sigma(U_g * [t,x] + W_g * S + b_g)     — update gate
  R = sigma(U_r * [t,x] + W_r * S + b_r)     — reset gate
  H = sigma(U_h * [t,x] + W_h * (S * R) + b_h)  — candidate

  S' = (1 - G) * H + Z * S                    — state update

Where sigma = tanh (the activation function) and * denotes element-wise
multiplication.

This is very similar to how an LSTM or GRU works in sequence modeling:
  - Z controls how much of the old state to keep
  - G controls how much to update
  - R resets parts of the state before computing the new candidate
  - H is the new candidate computed from both the input and the (reset) state

The full architecture:
  1. Initial layer: S^1 = tanh(W_0 * [t, x] + b_0)
  2. DGM layers (4 of them): S^{l+1} = DGMLayer(input=[t,x], S=S^l)
  3. Output: u = W_out * S^{L+1} + b_out  (a single scalar)

Default configuration: hidden size = 256, 4 DGM layers, tanh activation.

WHY TANH AND NOT RELU?

ReLU(x) = max(x, 0) has a ZERO second derivative everywhere (it's piecewise
linear). Since the PDE contains second derivatives d2u/dx2, using ReLU would
make those derivatives trivially zero, destroying the PDE residual entirely.
Tanh is smooth and has non-zero derivatives of all orders.


8. THE HARD TERMINAL CONSTRAINT
---------------------------------

The option price at maturity MUST equal the payoff: u(T, x) = Phi(x).

APPROACH 1 — SOFT CONSTRAINT (what most people do):
Add a penalty term to the loss: lambda_T * |u(T, x) - Phi(x)|^2

This works but requires tuning lambda_T carefully. Too small and the terminal
condition isn't satisfied; too large and the PDE residual is ignored.

APPROACH 2 — HARD CONSTRAINT (what we do):
Instead of letting the network learn the terminal condition, we FORCE it
structurally. We define:

    u_theta(t, x) = Phi(x) * exp(-r * (T-t)) + (T - t) * u_hat(t, x)

Where u_hat is the raw network output.

At t = T: the factor (T - t) = 0, so u_theta(T, x) = Phi(x) * exp(0) = Phi(x).
EXACTLY. Regardless of what the network outputs.

The term Phi(x) * exp(-r * tau) is the "discounted payoff" — it's already a
rough approximation to the true price (the price if there were no optionality).
The network only needs to learn the CORRECTION: (T-t) * u_hat, which is
smoother and easier.

This eliminates the terminal loss entirely — we only need J_PDE + J_boundary.


9. THE SMOOTHED PAYOFF TRICK
-------------------------------

The payoff Phi(x) = max(f(x), 0) has a KINK at f(x) = 0 (the at-the-money
point). The function max is not differentiable there.

WHY THIS IS A PROBLEM:

Since Phi(x) is embedded in the hard constraint, second derivatives of u_theta
pass through Phi. PyTorch's autograd computes:

    d2/dx2 [Phi(x) * exp(-r*tau)] = exp(-r*tau) * d2Phi/dx2

But d2/dx2 max(f, 0) contains a Dirac delta at f=0 — and PyTorch's torch.clamp
returns ZERO gradient at the kink. This produces WRONG PDE residuals, causing
the network to converge to an incorrect solution.

OUR FIX: Replace max(f, 0) with a smooth approximation during training:

    Phi_eps(x) = (1/2) * (f(x) + sqrt(f(x)^2 + eps^2))

This is smooth everywhere when eps > 0. As eps -> 0, it converges to max(f, 0).

We ANNEAL eps during training:
  - Start with eps = 0.1 (very smooth)
  - Linearly decrease to eps = 0 over the first 30% of training
  - After that, use the exact (non-smooth) payoff

This gives the network a smooth landscape to optimise in early training, then
sharpens the payoff for final accuracy.


10. THE HESSIAN COMPUTATION
----------------------------

The PDE operator contains the term:

    (1/2) * SUM_{i,j} A_ij * d2u/(dx_i * dx_j)

This requires the HESSIAN matrix H_ij = d2u/(dx_i * dx_j).

FOR LOW DIMENSIONS (d <= 5): We compute the full Hessian exactly. This requires
d backward passes through PyTorch's autograd. For d=2, that's just 2 backward
passes — very manageable.

FOR HIGH DIMENSIONS (d > 5): d backward passes becomes expensive. Instead, we
use HUTCHINSON'S TRACE ESTIMATOR. The key identity:

    trace(A * H) = E_v[ v^T * A * H * v ]

where v is a random vector with entries +1 or -1 (Rademacher distribution).

The product H*v (Hessian times vector) can be computed with a SINGLE backward
pass (it's a directional second derivative). So instead of d backward passes,
we use m=20 random vectors, requiring only 20 backward passes regardless of d.
This makes the method scale to d=100 or more.

IMPLEMENTATION: In pde/operator.py, the function black_scholes_operator()
automatically switches between exact Hessian (d <= 5) and Hutchinson (d > 5).


================================================================================
PART IV — TRAINING INFRASTRUCTURE
================================================================================

11. SAMPLING STRATEGY
---------------------

Traditional PDE solvers use a fixed grid. DGM instead samples random
"collocation points" where the PDE is evaluated. The quality of these samples
directly affects convergence.

We implement three samplers:

a) UNIFORM SAMPLER (samplers/uniform_sampler.py):
   Draws (t, x) uniformly from [0, T] x [x_min, x_max].
   Simple but wastes samples in regions where the solution is boring.

b) RISK-NEUTRAL SAMPLER (samplers/risk_neutral_sampler.py) — DEFAULT:
   Draws x from a Gaussian matching the risk-neutral distribution of log-prices:
     - Mean = (r - sigma^2/2) * T/2   (expected log-price at mid-maturity)
     - Covariance = rho * sigma * sigma^T * T  (diffusion covariance at maturity)
   
   This concentrates samples where asset prices are LIKELY to be, matching the
   PDE's own dynamics. Additionally, 20% of terminal samples are enriched near
   the at-the-money point (x ≈ 0), where the payoff kink causes the highest
   PDE residuals.

c) ADAPTIVE SAMPLER (samplers/adaptive_sampler.py):
   After a 2000-step warmup, evaluates the PDE residual on 10x candidate points
   and resamples proportionally to the squared residual. This automatically
   concentrates samples where the current solution is WORST.

WHY RISK-NEUTRAL BY DEFAULT: It provides a good balance between convergence
speed and simplicity. The adaptive sampler adds overhead from evaluating the
PDE residual on candidates, and the uniform sampler wastes too many points in
regions where the solution is nearly linear.


12. TRAINING PROTOCOL
---------------------

The training loop (training/trainer.py) uses a two-phase approach:

PHASE 1 (first 30% of steps):
  - Smoothed payoff with annealing eps from 0.1 to 0
  - Higher learning rates from cosine warm restarts
  - The smooth payoff gives clean gradients for initial learning

PHASE 2 (remaining 70%):
  - Exact payoff (eps = 0)
  - Lower learning rates for refinement
  - The network polishes the PDE approximation with true payoff

OPTIMISER: Adam with initial learning rate 1e-3.

LEARNING RATE SCHEDULE: Cosine annealing with warm restarts.
  - The LR follows a cosine curve from 1e-3 down to 1e-5
  - Every T_0 = 10,000 steps, it "restarts" back to 1e-3
  - Each subsequent cycle is 2x longer (T_mult = 2)
  - WHY: The periodic spikes help escape local minima. PDE loss landscapes
    are highly non-convex, and getting stuck in a bad local minimum gives a
    physically wrong solution.

GRADIENT CLIPPING: Max gradient norm = 1.0. PDE residuals can occasionally
spike (e.g., when a sample lands near the payoff kink), causing huge gradients.
Clipping prevents these spikes from destabilising training.

L-BFGS FINE-TUNING: After Adam finishes, we optionally run 300-500 steps of
L-BFGS (a quasi-Newton method). L-BFGS uses second-order information
(approximated Hessian) and converges much faster near a minimum. It typically
reduces the PDE residual by 1-2 orders of magnitude. The L-BFGS phase uses a
FIXED batch of collocation points (not resampled each step), so it's a
deterministic optimisation on a specific set of points.

BATCH SIZES:
  - 4096 interior collocation points (where PDE is enforced)
  - 1024 terminal points (where payoff condition is evaluated, soft case only)
  - 512 boundary points (where u -> 0 is enforced)

These sizes are a balance between per-step cost and gradient quality. Larger
batches give more stable gradients but cost more memory and compute.


13. LOSS FUNCTION WEIGHTS
--------------------------

The total loss is:

    J = lambda_PDE * J_PDE + lambda_boundary * J_boundary

With the hard terminal constraint, there is no terminal loss.

Default weights: lambda_PDE = 1.0, lambda_boundary = 1.0.

The boundary loss is much smaller in magnitude than the PDE loss (since the
network naturally produces near-zero values at extreme negative x), so equal
weights are sufficient.


================================================================================
PART V — EVALUATION AND BASELINES
================================================================================

14. MONTE CARLO REFERENCE PRICER
---------------------------------

To validate the DGM solution, we need "ground truth" prices. For multi-asset
options where no closed-form solution exists, we use Monte Carlo simulation.

The MC pricer (evaluation/monte_carlo.py) uses EXACT simulation — no Euler
discretisation. Under the risk-neutral measure:

    S_i(T) = S_i(0) * exp((r - sigma_i^2/2) * T + sigma_i * sqrt(T) * Z_i)

where Z = L * epsilon, L is the Cholesky factor of the correlation matrix rho,
and epsilon ~ N(0, I).

VARIANCE REDUCTION: We use antithetic variates — for every random draw epsilon,
we also use -epsilon. The two paths are negatively correlated, reducing variance
without additional simulation cost.

The MC pricer generates prices at multiple initial conditions S_0, creating a
"price surface" that the DGM solution is compared against.


15. ANALYTICAL SOLUTIONS
--------------------------

For cases where exact formulas exist, we use them for validation:

a) 1D BLACK-SCHOLES FORMULA (pde/analytical.py):
   V = S * Phi(d1) - K * exp(-r*tau) * Phi(d2)
   where d1, d2 are the standard BS d-values and Phi is the standard normal CDF.

b) GEOMETRIC BASKET CALL:
   The geometric average (prod S_i)^(1/d) follows a single GBM with effective
   parameters sigma_geo and r_geo. So the geometric basket call reduces to a
   1D Black-Scholes problem — giving us a closed-form solution in multiple
   dimensions.

c) GREEKS (Delta, Gamma):
   Delta = Phi(d1) and Gamma = phi(d1) / (S * sigma * sqrt(tau))
   where phi is the standard normal PDF.

These serve as ground truth for the validation experiments.


16. ZHOU ET AL. (2021) BASELINE
---------------------------------

Zhou et al. proposed a DIFFERENT approach: instead of solving the PDE, train
a neural network to regress MC-generated prices.

Their method (baselines/zhou_et_al.py):
  1. Generate 100,000 random initial conditions S_0
  2. For each S_0, run 50 MC paths and average to get label V(0, S_0)
  3. Train a 4-layer feedforward NN to predict V from S_0 via MSE loss

KEY DIFFERENCES FROM DGM:
  - Zhou's method only gives prices at t=0 (not the full time evolution)
  - Zhou requires running millions of MC paths to generate training data
  - Zhou cannot compute Greeks (no autograd through the PDE operator)
  - Zhou's labels are noisy (averaged MC paths), limiting accuracy
  - DGM needs ZERO MC paths during training — the PDE itself is the loss

We replicate Zhou's method and compare side-by-side with DGM.


================================================================================
PART VI — SUPPORTED PAYOFF FUNCTIONS
================================================================================

17. PAYOFF TYPES
-----------------

All payoffs are implemented in pde/payoffs.py and operate in log-price
coordinates x_i = log(S_i / K):

a) ARITHMETIC BASKET CALL (default):
   Phi(x) = K * max( (1/d) * SUM exp(x_i) - 1, 0 )
   This is the average of asset prices minus the strike.
   No closed-form price — must use MC or DGM.

b) GEOMETRIC BASKET CALL:
   Phi(x) = K * max( exp(mean(x)) - 1, 0 )
   The geometric mean of prices minus the strike.
   HAS a closed-form price — used for validation.

c) MAX CALL (BEST-OF):
   Phi(x) = K * max( max_i exp(x_i) - 1, 0 )
   The best-performing asset minus the strike.
   No closed-form — MC or DGM only.

d) SPREAD OPTION (d=2 only):
   Phi(x) = max( K*exp(x_1) - K*exp(x_2) - K, 0 )
   The difference between two assets minus the strike.
   No closed-form — MC or DGM only.

Each payoff comes in two versions:
  - CLIPPED: with max(., 0) applied (for inference/evaluation)
  - UNCLIPPED: without the max (for the smoothed payoff trick during training)


================================================================================
PART VII — GREEKS COMPUTATION
================================================================================

18. WHAT ARE GREEKS?
--------------------

"Greeks" are the sensitivities of the option price to its inputs:

  DELTA = dV/dS   (how much price changes when the asset moves by $1)
  GAMMA = d2V/dS2 (how fast delta itself changes — the "convexity")

Traders use delta for hedging (how many shares to hold to offset option risk)
and gamma for risk management (how stable the hedge is).

Traditionally, Greeks are computed by finite differences (bump S by a small
amount, reprice, divide by the bump). This is noisy and expensive.

WITH DGM: Since u_theta is a differentiable neural network, we get Greeks
FOR FREE via automatic differentiation:

  Delta_i = (1/S_i) * du/dx_i
  Gamma_i = (1/S_i^2) * (d2u/dx_i^2 - du/dx_i)

The 1/S_i factors come from the chain rule of the log-price transformation.
These are exact (up to the network's approximation quality) and require no
additional MC simulation or finite differencing.

24. EXPERIMENT 6: ABLATION STUDY
---------------------------------

File: experiments/run_ablations.py

PURPOSE: Isolate the effect of individual design choices.

Setup: d=2, basket call, 50k steps (no L-BFGS), MC reference.

RESULTS:
  DGM + tanh:     3.89% error  (converged)
  DGM + softplus: DIVERGED (NaN at step ~30k)
  MLP + tanh:     3.38% error  (converged)

KEY FINDINGS:
  - Softplus activation is UNSTABLE for PDE solving. The unbounded softplus
    output, combined with cosine LR restarts, causes the PDE residual to
    explode. Tanh's bounded range [-1, 1] provides critical stability.
  - MLP is competitive with DGM at d=2. The DGM architecture's advantage
    emerges at higher dimensions where input re-injection prevents gradient
    degradation through deep networks.


25. EXPERIMENT 7: HYBRID DGM + MONTE CARLO
--------------------------------------------

File: experiments/run_hybrid_mc.py

PURPOSE: Demonstrate that even an imperfect DGM solution can dramatically
improve Monte Carlo accuracy via the control variate technique.

IDEA: If we have an approximate solution u_theta that is correlated with the
true price, we can use it as a "control variate":

    Improved estimate = MC_estimate + c* * (u_theta - E[u_theta])

where c* is chosen to minimise variance.

Setup: d=2, DGM trained 50k steps, applied to 100k MC paths.

RESULTS:
  Vanilla MC:   price=0.09046, standard error=3.80e-4
  CV MC:        price=0.09046, standard error=2.37e-6

  VARIANCE REDUCTION: 99.99%

This is the most practically important result. Even a rough DGM solution
(trained for only 50k steps) reduces MC variance by a factor of 160x. In
practice, this means you can get the same accuracy with 160x fewer MC paths,
saving enormous computation.

PART IX — CODE STRUCTURE AND WHY EACH MODULE EXISTS
================================================================================

26. MODULE-BY-MODULE EXPLANATION
---------------------------------

configs/base_config.py:
  WHY: Centralises ALL tunable parameters in one place. No magic numbers
  scattered through the code. Uses Python dataclasses for type safety and
  OmegaConf for YAML loading.

models/dgm_layer.py:
  WHY: One file per architectural component. The DGM layer is self-contained
  with its own weight initialisation, making it easy to test in isolation.

models/dgm_network.py:
  WHY: Assembles DGM layers into a full network with the hard terminal
  constraint. Separates the raw network output (_raw_output) from the
  constrained output (forward), which is important for debugging.

models/mlp_network.py:
  WHY: Provides a baseline for the ablation study. Uses the same interface
  (forward, get_price, get_delta, get_gamma) as DGMNetwork, so experiments
  can swap architectures without code changes.

models/model_factory.py:
  WHY: A single entry point for model construction. Experiment scripts call
  build_model(config) and don't need to know which architecture they're using.

pde/operator.py:
  WHY: The most mathematically critical file. Isolating the PDE operator makes
  it easy to unit test (we can verify L[u]=0 for known solutions).

pde/analytical.py:
  WHY: Ground truth. Functions here are standard textbook formulas, used for
  validation experiments and Greeks accuracy testing.

pde/payoffs.py:
  WHY: Separating payoffs from the network allows easy extension to new option
  types. The registry pattern (PAYOFF_REGISTRY) makes adding new payoffs a
  one-line change.

pde/boundary.py:
  WHY: Domain truncation logic (how wide should the computational domain be?)
  is separate from sampling and loss computation.

losses/pde_loss.py, terminal_loss.py, boundary_loss.py, combined_loss.py:
  WHY: Each loss component is independently testable and logically separate.
  combined_loss.py assembles them with user-specified weights.

samplers/base_sampler.py:
  WHY: Abstract interface ensures all samplers provide the same methods
  (sample_interior, sample_terminal, sample_boundary).

samplers/risk_neutral_sampler.py:
  WHY: The default sampler matches the PDE's own dynamics, concentrating
  points where the solution varies most.

samplers/adaptive_sampler.py:
  WHY: Advanced sampler that focuses on high-residual regions. Uses the
  decorator pattern (wraps a base sampler).

training/trainer.py:
  WHY: The main training loop is the most complex component. It manages:
  - Two-phase training (smooth -> exact payoff)
  - Periodic evaluation against MC reference
  - Checkpointing the best model
  - L-BFGS fine-tuning
  - NaN detection
  Centralising this logic prevents experiments from duplicating training code.

training/scheduler.py:
  WHY: Separates LR schedule construction from the training loop.

training/callbacks.py:
  WHY: Checkpointing and early stopping are reusable across experiments.

evaluation/monte_carlo.py:
  WHY: Clean, tested MC pricer with exact simulation and variance reduction.
  Reused by all experiments that need reference prices.

evaluation/metrics.py:
  WHY: Consistent error metrics (relative L2, max pointwise, mean relative)
  across all experiments.

baselines/zhou_et_al.py:
  WHY: Self-contained replication of the Zhou et al. method for comparison.

experiments/run_*.py:
  WHY: Each experiment is a standalone script with argparse. Users can run
  any experiment independently without understanding the full codebase.

plotting/:
  WHY: Publication-quality figures with consistent styling. Each plot function
  saves both PNG (for README) and PDF (for papers).


================================================================================
PART X — KEY DESIGN DECISIONS SUMMARISED
================================================================================

DECISION                             REASON
---------------------------------------------------------------------------
Log-price coordinates                Constant PDE coefficients; better NN conditioning
Tanh activation                      Non-zero second derivative required for PDE
Hard terminal constraint             Exact enforcement; eliminates a loss component
Smoothed payoff annealing            Non-differentiable kink breaks autograd Hessian
Risk-neutral sampling (default)      Concentrates points where solution varies most
Cosine warm restarts                 Escape local minima in non-convex PDE loss
L-BFGS fine-tuning                   Second-order method converges faster near minimum
Hutchinson estimator (d > 5)         Avoids O(d) backward passes; cost O(m) independent of d
Xavier initialisation                Maintains variance through tanh layers
Gradient clipping (norm 1.0)         Prevents PDE spikes from destabilising training
4 DGM layers, 256 hidden             Balance between expressiveness and training cost
Batch size 4096/1024/512             Balance between gradient quality and memory
Antithetic variates in MC            Free variance reduction for reference prices
50-path averaged labels (Zhou)       Reduces label noise in regression baseline
